# Прочитать проект за 15 минут

Начните с одного законченного пути. Ниже — конкретные файлы, вопросы для ревью
и проверки поведения. Полная [архитектура](ARCHITECTURE.md) объясняет границы,
а [возможности](FEATURES.md) — задачи пользователей.

## 1. React: интерфейс при медленной и нестабильной сети

Откройте [HTTP-транспорт](../apps/web/src/lib/api/http-transport.ts),
[обновление сессии](../apps/web/src/lib/api/http-browser-session.ts)
и [область запроса ИИ](../apps/web/src/features/ai-employee/hooks/useAIEmployeeRequestScope.ts).

Посмотрите, как объединены AbortSignal, тайм-аут и ограниченные повторы чтения,
почему команды записи не повторяются транспортом вслепую и как обновление
сессии объединяет конкурентные запросы. Затем проверьте, как смена проекта
или диалога делает предыдущий асинхронный результат неактуальным.

Проверка: [ошибка отправки и мобильный чат](../apps/web/e2e/product-polish.spec.ts),
[повтор отправки виджета](../apps/web/e2e/public-chat-retry.spec.ts).

## 2. Go: бизнес-инвариант при конкурирующих запросах

[Архивирование задачи](../apps/api/internal/modules/worktracker/service/task_archive.go)
показывает предметную логику без абстрактного CRUD: у задачи с работающим таймером
нельзя потерять рабочий контекст. Найдите блокировку строки, проверку доступа
после чтения, транзакционную запись события и обработку повторной команды.

Проверка: [интеграционные тесты архивирования](../apps/api/internal/integrationtests/worktracker/task_archive_integration_test.go).
Вопрос для ревью: останется ли правило верным, если одновременно придут удаление
и запуск таймера? Проверка только в UI не решает эту задачу.

## 3. Python + gRPC: ИИ от запроса до сохранённой задачи

Читайте по порядку:

1. [AgentRuntime](../contracts/proto/ai_agent/v1/agent_runtime.proto):
   StartTurn, ResumeTurn, поток событий и контекст выполнения.
2. [Граф LangGraph](../apps/ai-agent/src/pulse_agent/graph/builder.py):
   переходы, предложение и продолжение после подтверждения.
3. [Checkpoint](../apps/ai-agent/src/pulse_agent/checkpointing.py):
   сохранение состояния диалога.
4. [Контракт инструментов](../contracts/proto/ai_agent/v1/pulse_tools.proto)
   и [Go-модуль](../apps/api/internal/modules/ai): серверная граница исполнения.
5. [Карточки React](../apps/web/src/features/ai-employee): предложение,
   редактирование полей, подтверждение и ссылка на результат.

Вопрос для ревью: кто разрешает запись — модель или доменный сервер?
Ответ должен следовать из кода, а не из системного промпта.
[Видеосценарий и способ записи](TECH_SHOWCASE.md) отделяют реальный путь
Python/gRPC/Go от отсутствующего в этой записи внешнего вызова LLM.

## 4. Runtime: что происходит после падения worker

[Получение задания](../apps/api/internal/runtime/kernel/claim.go) использует
блокировку с пропуском занятых строк, аренду и fencing token.
[Журнал эффектов](../apps/api/internal/runtime/effects/ledger.go) сохраняет
не только успех/ошибку, но и неопределённый результат внешней операции.

Вопрос для ревью: что делать, если провайдер выполнил действие, но HTTP-ответ
потерян? Идемпотентность и сверка — часть протокола с провайдером. Транзакция
PostgreSQL не может откатить уже отправленное внешнее сообщение.

Проверка: [тесты журнала](../apps/api/internal/runtime/effects/ledger_test.go),
[границы lease](architecture/runtime-claim-leases.md).

## 5. Финансы: расширение без фиктивного банковского API

[Сервис черновиков](../apps/api/internal/modules/clients/service/bank_invoices.go),
[права](../apps/api/internal/platform/authz/payment_finance.go),
[контракт адаптера](../apps/api/internal/modules/clients/invoicing/provider.go).

Проверьте серверную сумму/валюту, ожидаемую ревизию, повтор с тем же ключом
и различие между «черновик сохранён» и «счёт выпущен банком».
`Lookup` нужен для восстановления результата после неопределённого ответа.

Проверка: [PostgreSQL-конкуренция и права](../apps/api/internal/integrationtests/clients/bank_invoices_integration_test.go),
[потерянный ответ в браузере](../apps/web/e2e/bank-invoice.spec.ts).

## 6. Честные границы решения

[Реестр владения](architecture/module-ownership.tsv),
[исключения](architecture/module-ownership-exceptions.tsv)
и [контракты чтения](architecture/controlled-module-boundaries.md) описывают границы модулей.
Проверка проходит без исключений; [функциональные ограничения](LIMITATIONS.md) раскрыты отдельно.

GitHub используется для хранения исходников и просмотра изменений. Автоматические
Actions отключены; воспроизведение проверок остаётся локальным. Результаты
[зафиксированы отдельно](VALIDATION.md), без подмены фактов зелёным значком.

## 7. SDK как внешняя граница продукта

[SDK и примеры](../sdk/README.md), [контракт из 16 операций](../sdk/openapi.json),
[транспорт TypeScript](../sdk/typescript/src/index.ts),
[транспорт Python](../sdk/python/src/pulse_sdk/client.py).

Обратите внимание на запрет перенаправлений с токеном, отсутствие автоматических
повторов записи и отдельный метод подтверждения ИИ. Сгенерированные клиенты
отделены от ручных; источник, версия генератора и ограничения проверки указаны
явно. Число языков не подменяет проверку поведения каждого клиента.
