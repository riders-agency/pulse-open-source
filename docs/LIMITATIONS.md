# Известные ограничения

- Для выставления счетов непосредственно в банке нужны выбранный банк,
  соответствующий адаптер и серверные реквизиты доступа. Сейчас доступны учёт
  оплат, документы и сохраняемые банковские черновики с общим контрактом адаптера.
  Выпуск в банке отключён; работающий банковский API не заявляется.
  [Сценарий и критерии реализации](BANK_INVOICES.md).
- Python-оркестратор и модель требуют отдельной настройки. Без неё приложение
  должно показывать ограниченную доступность, а не имитировать ответы.
- Внешние сервисы, голосовая связь, доставка почты и банковские операции нельзя
  считать проверенными только по локальным тестам.
- Публичная начальная миграция предназначена для пустой БД. Применять её вместо
  истории миграций существующей закрытой установки нельзя.
- Проверка секретов снижает риск утечки, но не заменяет управление ключами и
  ротацию при реальном инциденте. Не прикладывайте рабочие дампы к issues.

- Публичный репозиторий создан из чистого снимка, без прежней закрытой истории.
  Область проверки и её границы раскрыты в [отчёте](REPOSITORY_AUDIT.md).
- Открытое демо использует APInet с суточным бюджетом; при его исчерпании
  ответы модели недоступны до следующего дня UTC. Внешние отправки, загрузки
  и запуск сценариев закрыты. [Устройство демо](PUBLIC_DEMO.md).
