# ADR: команды владельца и контракты чтения

Статус: принято. Область: Go API, модульный монолит, PostgreSQL.

## Решение

Модуль владеет изменениями своих таблиц. Соседние модули вызывают его типизированные
команды, передавая текущую транзакцию. Составная операция не делает промежуточных
commit. `platform/uow.Run` фиксирует бизнес-изменения и outbox вместе;
`Savepoint` отделяет неуспешную команду от записи результата её попытки.
Уведомление worker откладывается до commit. Репозитории не начинают транзакции
и не импортируют HTTP-клиент или outbox.

Для списков, отчётов и проверки связей используются версионированные SQL-проекции
`pulse_read.*_v1`. Это сознательный контракт чтения внутри одного PostgreSQL,
позволяющий выполнять join одним запросом без N+1. Каждая проекция имеет владельца,
явный перечень столбцов и потребителей. Контракт расположен в `contracts/read_models.json`
владельца; общий реестр — `read-contracts.json`. Миграция 115 создаёт представления
с `OFFSET 0`: PostgreSQL запрещает INSERT/UPDATE/DELETE через них.

Проекции не являются API авторизации или изоляцией на уровне разных DB-ролей.
Доступ к компании, проекту, процессу и конкретному объекту проверяет Go.
`security_barrier` и отсутствие паролей, токенов и шифротекста в проекциях
уменьшают поверхность доступа, но не заменяют эти проверки.
Секрет интеграции читает отдельный внутренний порт владельца, после разрешения
конкретной интеграции. Он не включается в API-ответ или JSON трассировки.

Проверка `check-module-contracts` запрещает прямые обращения к чужим базовым
таблицам (включая `public.table`), запись через проекции и незарегистрированных
потребителей. Она сверяет проекцию с миграцией и контрактом владельца.
Список прежних исключений пуст: сроки не продлены и проверки не отключены.
Межмодульные приёмочные тесты находятся в `internal/integrationtests`; обычные
модульные проверки остаются рядом с кодом. Все запускаются через `go test ./...`.

## Следствия

- Изменение базовой таблицы требует сохранить опубликованные поля проекции.
- Несовместимое изменение требует новой версии контракта и миграции потребителей.
- Удаление поля не может незаметно изменить `SELECT *`: в миграции указаны столбцы.
- Разделение на независимые базы в будущем потребует замены этих read-контрактов;
  сейчас система намеренно является модульным монолитом.
- Низкоуровневые команды принимают транзакцию; прикладной сервис отвечает за
  авторизованный сценарий. Наличие внутреннего Go-порта не даёт внешнему пользователю прав.

## Проверка

Тест PostgreSQL проверяет все 20 проекций на запрет записи и отсутствие колонок
с секретами. Тесты подтверждения запускают восемь одновременных запросов и проверяют
ровно один результат. Инъекция ошибки записи квитанции доказывает откат бизнес-изменения.
Проверки прав покрывают отключённого сотрудника, пустой allowlist, аудитора,
неактивное членство и чужой проект. Проверка `-race` выполняется на Go-пакетах.
