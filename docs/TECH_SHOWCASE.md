# Техническая витрина `/tech`

Публичный маршрут Next.js открывается без авторизации и без запросов к рабочим
данным. Представляет Pulse как платформу для ИИ-агентов и показывает пять записей:

1. Пользователь просит запланировать задачу обычными словами, получает карточку
   и подтверждает её сообщением «Да, создавай». Сотрудник создаёт задачу в чате.
   Только после результата открывается граф. Под записью — интерактивные шаги
   этого же выполнения и фактический расход токенов APInet. Перезагрузка и
   переход в карточку проверяют сохранённый результат в Go / PostgreSQL.
2. Отключение действия сценария и сохранение настройки после перезагрузки.
3. Чат оператора: набранный текст переживает сетевой сбой. Посетитель, ответы
   чат-API и ошибка синтетические; запись не подтверждает внешнюю доставку.
4. Черновик банковского счёта: реквизиты и срок сохраняются в PostgreSQL.
   Выпуск в банке отключён до подключения проверенного адаптера.
5. Почта и ИИ-отделы: обычный сценарий демо-компании получает учебное письмо,
   классифицирует его через модель, готовит страницу и счёт, ждёт человека,
   сохраняет результаты. [Границы, исходники и воспроизведение](AGENT_OFFICE.md).

Главная запись видна на первом экране. Видео не запускаются автоматически;
для главной записи загружаются метаданные, остальные ждут воспроизведения.
После записи размещён официальный логотип LangGraph: именно этот фреймворк
исполняет граф ИИ-сотрудника в Python и приостанавливает его для подтверждения.
Под графом открыты 12 разделов возможностей и дополнительные сценарии;
в них по умолчанию выбран редактор сценария. Подробная архитектура свёрнута.
У каждой записи есть постер, русские текстовые пояснения и файл WebVTT.
Сценарии переключаются с клавиатуры стрелками, Home и End. Контракты раскрываются
рядом с записью; исходники доступны по ссылкам на репозиторий.

## Повторная запись

Живой ИИ-сценарий: из `apps/web` запустите `node scripts/record-agent-demo.mjs`.
После просмотра результата выполните `node scripts/publish-agent-recording.mjs`:
скрипт проверяет свидетельства выполнения, обрезает вход и проверку после
перезагрузки, создаёт MP4, постер, титры и JSON трассировки. Нужен FFmpeg.
Скрипт разрешает только localhost или выделенный preprod, создаёт отдельного
демогостя, проверяет usage, остановку инструмента, подтверждение словами
и сохранённый результат. evidence.json содержит время этапов и ограниченную
трассировку: названия узлов, инструментов, модель и счётчики, без учётных данных.
Публичный taskRecording.generated.json создаётся из проверенной записи; числа
и маршрут не заполняются вручную. Видеомонтаж удаляет только вход и проверку
после перезагрузки, не ускоряя работу сотрудника.
Доступ к модели уже должен быть настроен на сервере; скрипт не принимает ключи.

Для остальных записей и сценарного ИИ без внешней модели:

Используйте только изолированную локальную установку с вымышленными данными.
Скрипт отклоняет адреса вне localhost / 127.0.0.1, создаёт задачи и сценарии.
Для финансов заранее создайте синтетическую неоплаченную оплату. Настройте
Python runtime и checkpoint PostgreSQL согласно `apps/ai-agent/README.md`.
Сценарный путь требует активных ToolGateway, checkpoint и resume; внешняя модель
для этой записи не требуется. Рабочие ключи банков и моделей не нужны.

Из `apps/web`:

```bash
export PULSE_BASE_URL=http://127.0.0.1:19821
export PULSE_OWNER_EMAIL=demo@example.test
# Задайте свой пароль через окружение, не сохраняйте его в истории или репозитории.
export PULSE_WORK_COMPANY_ID=<uuid-компании>
export PULSE_WORK_PROJECT_ID=<uuid-проекта>
export PULSE_PAYMENT_ACTION_ID=<uuid-тестовой-оплаты>
node scripts/record-tech.mjs ai-task
node scripts/record-tech.mjs workflow
node scripts/record-tech.mjs chat
node scripts/record-tech.mjs invoice
```

`PULSE_OWNER_PASSWORD` обязателен. Требуется Chrome, доступный Playwright.
Сырые WebM, снимки и доказательство создания задачи сохраняются в игнорируемый
`artifacts/tech`; cookies и пароль в видеозапись не попадают. MP4/H.264, постеры
WebP и пояснения находятся в `apps/web/public/tech/recordings`. Перед заменой
публичных записей просмотрите их целиком и убедитесь, что данные вымышленные.
Не используйте эти скрипты с туннелем к рабочему серверу.

## Проверки

`e2e/tech.spec.ts` проверяет публичный маршрут, клавиатурное переключение,
ограничения банковской интеграции, наличие всех видео/постеров/пояснений и
отсутствие горизонтальной прокрутки на 320, 390, 768 и 1440 px.
`record-tech.mjs ai-task` проверяет статус `succeeded`, ссылку на созданную
задачу и доступность её страницы. Остальные записи проверяют конечное состояние
интерфейса, а не только факт клика.

## Запись почтового сценария

Почтовый сценарий теперь выполняется в демо-компании, в `/project-workflows`.
Старый `/tech/office` перенаправляет туда. Отдельный пример с собственным
сервером и хранилищем удалён. Запись показывает настоящий Go workflow,
Python/LangGraph, ожидание решения и сохранённый результат. Ожидание опроса
и переходы между экранами сокращены монтажом; статусы и результаты реальные.

```bash
PULSE_RECORD_DEMO=1 PULSE_BASE_URL=https://demo.example.test pnpm test:e2e e2e/demo.spec.ts
node scripts/publish-office-recording.mjs
```

Запускайте из `apps/web` только против изолированного демостенда. Проверка
подтверждает оба решения человека, изоляцию гостей и повторную доставку письма.
