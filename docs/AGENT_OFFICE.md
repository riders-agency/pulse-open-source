# ИИ-отделы: от письма до результата

Pulse — платформа для ИИ-агентов. [Посмотреть запись](https://pulse.riders.agency/tech#office-scenario)
и [разобрать выполненный запуск](https://pulse.riders.agency/tech/office) можно без входа.

В этом исполняемом примере приходит учебное письмо: добавить услугу на сайт
и подготовить счёт по заказу. Python действительно запускает LangGraph,
модель вызывается через существующий Go ModelGateway по gRPC, а результаты
сохраняются в отдельной SQLite-базе примера. В браузер не попадают ключи провайдера.

## Что выполняется

1. Наблюдатель проверяет локальный учебный почтовый ящик каждые 500 мс.
2. Модель классифицирует письмо. Сервер проверяет перечень отделов и формат ответа.
3. Диспетчер передаёт поручения отделам. ИИ-отдел отдельно вызывает модель,
   готовит текст страницы и передаёт его инструменту `website.prepare`.
4. Бухгалтерия вызывает `invoice.prepare`. Сумма берётся из заказа, а не из ответа модели.
5. `interrupt()` останавливает LangGraph перед изменениями. Видны оба черновика.
6. После подтверждения `office.apply` атомарно сохраняет страницу и черновик счёта.
   Учебный сайт читает опубликованный текст из этой базы. Отказ пропускает запись.
7. `receipt.read` читает сохранённые результаты. Повторное решение не создаёт копии.

Граф на экране получает переходы из `graph.get_graph()`, статусы — из журнала
реального запуска. Для классификации и подготовки страницы показан расход токенов,
возвращённый провайдером. Публичная страница воспроизводит этот журнал и видео;
кнопка воспроизведения не запускает новую модель и не изменяет данные.

## Права и границы

У диспетчера есть чтение ящика и маршрутизация; у ИИ-отдела — подготовка страницы;
у бухгалтерии — подготовка счёта. Только контроллер графа может применить решение
человека. Модель получает текст письма как недоверенные данные и возвращает
проверяемую структуру; доступа к базе и произвольному выполнению кода у неё нет.

Это отдельный учебный адаптер, не подключение к настоящей почте, CMS или банку.
Отправка писем и выпуск банковского счёта здесь отсутствуют. Плательщик, заказ,
сумма и письмо вымышлены. Для реального внедрения нужны провайдеры и их права,
защищённая очередь, аутентификация оператора и долговечное хранение ожиданий.
Основной агент Pulse уже использует сессии Go, проверку доступа к проектам,
gRPC и PostgreSQL checkpoints; пример не заменяет этот контур.

Локальный сервер привязан к `127.0.0.1:19862`, проверяет `Host`, `Origin` и тип
запроса. Управление доступно только странице разработки на `127.0.0.1:19861`.
В production Next.js не включает этот адрес. База результатов сохраняется на диске,
но checkpoint учебного процесса хранится в памяти: незавершённый запуск после
перезапуска сервера не возобновляется. Для новой записи нужна новая папка данных.

## Запуск из исходников

Реализация: [`apps/ai-agent/examples/office_demo`](../apps/ai-agent/examples/office_demo).

В закрытом окружении задайте адрес и сервисный токен **вашего** ModelGateway:
`PULSE_MODEL_GATEWAY_GRPC_ADDR`, `AI_AGENT_SERVICE_TOKEN`. Задайте идентификаторы
своей учебной компании, проекта, пользователя и сессии в `OFFICE_COMPANY_ID`,
`OFFICE_PROJECT_ID`, `OFFICE_USER_ID`, `OFFICE_SESSION_ID`. Эти значения не должны
попадать в видео, JSON записи или репозиторий. Проект должен иметь подключённую модель.

```bash
cd apps/ai-agent
uv sync --locked
PYTHONPATH=examples OFFICE_DEMO_DIRECTORY=/tmp/pulse-office-demo uv run python -m office_demo.server
```

В другом терминале из корня репозитория:

```bash
PULSE_OFFICE_DEMO_URL=http://127.0.0.1:19862 pnpm --dir apps/web dev --hostname 127.0.0.1 --port 19861
```

Откройте `http://127.0.0.1:19861/tech/office`: запустите наблюдение, получите
учебное письмо и подтвердите либо отклоните изменения. После подтверждения
ссылка «Открыть учебный сайт» показывает страницу из сохранённых результатов.

## Проверки и запись

```bash
uv run --directory apps/ai-agent pytest examples/office_demo -q
uv run --directory apps/ai-agent ruff check examples/office_demo
cd apps/web
node scripts/record-office-demo.mjs
node scripts/publish-office-recording.mjs ../../artifacts/tech/office
```

Проверки покрывают отсутствие записей до подтверждения, отказ, права отделов,
отклонение недопустимых полей модели, сбой модели, повторную доставку и сохранение
результатов после открытия базы заново. Запись дополнительно проверяет два
настоящих ответа модели с токенами, изменение учебного сайта и запрет повторного
решения/чужого Origin. Мок модели используется только в модульных тестах.
