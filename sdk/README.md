# SDK Pulse

Клиенты публичного HTTP API: авторизация, задачи и ИИ-сотрудник. Сервер проверяет
права; SDK не обращается к Python, gRPC и провайдеру модели напрямую.

## TypeScript, JavaScript и Python

- [TypeScript / JavaScript](typescript/README.md): Node.js, типы, таймаут,
  отмена запроса, обработка ошибок, запрет перенаправлений с Bearer-токеном.
- [Python](python/README.md): синхронный клиент без внешних зависимостей,
  задачи, диалог и отдельные методы принятия/отклонения предложения.

Пакеты доступны в отдельных публичных репозиториях с релизами `v0.1.0`:
[TypeScript/JavaScript](https://github.com/riders-agency/pulse-sdk-typescript),
[Python](https://github.com/riders-agency/pulse-sdk-python),
[PHP / Composer](https://github.com/riders-agency/pulse-sdk-php),
[Go](https://github.com/riders-agency/pulse-sdk-go).
[PHP SDK опубликован в Packagist](https://packagist.org/packages/riders-agency/pulse-sdk)
и устанавливается командой `composer require riders-agency/pulse-sdk:^0.1`.
TypeScript/JavaScript и Python доступны из GitHub; публикация в каталогах
npm/PyPI требует авторизации владельца. Способы установки описаны в README пакетов.

[Фреймворки и готовые подключения](frameworks/README.md): Next.js, NestJS,
Express, Fastify, Nuxt, SvelteKit, React, Vue, Angular, Svelte, FastAPI,
Django, Flask, Laravel, Symfony, Gin, Echo и рецепты для нативных клиентов.

## Go, PHP, C#, Rust, Swift, Dart и Ruby

Клиенты в `generated/` получены из [проверяемого JSON-контракта](openapi.json).
У каждого есть собственная инструкция установки, модели и документация методов.
Контракт содержит 16 операций: вход/выход, профиль, жизненный цикл задач,
ИИ-сессии, сообщение, отмена и решения по предложениям. Это явно выделенная
часть API; полный перечень маршрутов продукта шире.

Генерация закреплена на OpenAPI Generator 7.20.0 в контейнере с закреплённым digest.
Повторить в новом каталоге (Docker либо Podman, Python 3.12+):

```bash
python3 sdk/generate.py all --output /tmp/pulse-sdk-generated
# Или один язык:
python3 sdk/generate.py go --output /tmp/pulse-sdk-go
```

Прямое редактирование сгенерированных клиентов не рекомендуется: исправьте
контракт или параметры генерации и пересоздайте каталог. Генератор никогда
не перезаписывает существующий каталог. Workflow-файлы GitHub не включаются.

## Подключение и подтверждение ИИ

Укажите origin своей установки и Bearer access token либо API-ключ с нужными
правами. В демо регистрация гостя доступна через интерфейс, выпуск API-ключей
отключён. Серверные токены нельзя встраивать в публичные мобильные/веб-клиенты:
такие приложения должны получать пользовательскую сессию через свою авторизацию.

1. Создайте ИИ-сессию в выбранном проекте.
2. Отправьте сообщение. Сохраните ID сессии для последующего чтения.
3. Покажите `tool_calls` со статусом `pending_approval` и их `input_json`.
4. После решения пользователя отдельно вызовите `approveProposal` или `rejectProposal`.
5. Прочитайте обновлённую сессию и результат инструмента.

Клиенты не выбирают решение за пользователя. При таймауте действие могло
успеть выполниться: сначала прочитайте состояние, затем решайте о повторе.
SSE и загрузка файлов не входят в контракт SDK 0.1.

## Статус проверки

TypeScript/Python имеют исполняемые тесты транспорта: авторизация, кириллица,
архив/восстановление, ошибки, запрет редиректа, отсутствие автоматических
повторов и подтверждений. Для остальных клиентов статус генерации и проверки
сборки зафиксирован в [VALIDATION](../docs/VALIDATION.md). Успешная генерация
сама по себе не означает проверку всех языковых сред и всех операций.

Сгенерированные транспорты используют настройки своих библиотек: настройте
HTTPS, таймауты и запрет редиректов, отключите отладочную печать тел/заголовков.
Они не наследуют политику ручных клиентов TypeScript/Python автоматически.
Старый отдельный PHP-пакет `ridersagency/pulseclient` использует прежний `/send`
и не является клиентом современного API v1; его история в этот снимок не включена.

Основа генерации: [официальный список генераторов](https://openapi-generator.tech/docs/generators/).
Набор охватывает распространённые веб-, серверные и мобильные экосистемы;
он не заявляется рейтингом языков.

Повторить основные локальные проверки: `bash scripts/check-sdk.sh`.
При изменении серверного API обновляйте `sdk/openapi.json` вместе с контрактами
приложения. Проверка SDK сверяет маршруты, ссылки схем и хеши генерации;
проверку совместимости ответов обеспечивают интеграционные сценарии.
